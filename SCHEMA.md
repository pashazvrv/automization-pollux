# Схема атомизации

Запрос раскладывается на четыре класса:

| класс | поле | что это |
|---|---|---|
| Task | `tasks` | самостоятельные действия с проверяемым результатом |
| Task constraints | `task_constraints` | требования к СОДЕРЖАНИЮ, привязанные к этой задаче и её материалу |
| Format constraints | `format_constraints` | требования к ФОРМЕ ответа, переносимые на любую задачу |
| Context | `context` | `data` (материал), `background` (фон), `role` (роль модели) |

## Правила
1. **Запись.** Задачи и ограничения в разметке хранятся ТОЛЬКО в согласованной форме (`norm`, см. ниже).
   Контекст (`data`, `background`, `role`) — точные подстроки запроса. Внутри пайплайна у задачи есть `frags`,
   у ограничения — `src`: дословные куски, из которых они взяты; по ним `src/validate.py` проверяет, что ничего
   не выдумано и не потеряно. Длинные (>200 символов) куски пишутся якорем: пять слов + `……` + пять слов.
   (Решение пользователя, 03.11.2026.)
2. **Transfer-тест** (task vs format). Требование — format, если оно описывает форму ответа
   (объём, структура, язык, стиль, тон, оформление, адресат) и сохраняет смысл при переносе на любую другую
   задачу. Если оно говорит о содержании, зависит от объекта или действия этой задачи
   («сохрани детали оригинала», «с упором на риски», «опирайся на личный опыт») — task.
   Решается по конкретному вхождению, а не по типу.
   Язык ответа («на английском») — format; язык программирования, имя метода, сигнатура, сложность — task (бессмысленны вне задачи на код).
3. **Роль** («представь, что ты юрист», «от лица зоозащитника») — не ограничение, а `context.role`.
   Характеристики персонажа и обстановка вокруг роли — `background`. (Решение пользователя, 01.10.2026.)
4. **Пустые классы — норма.** Запрос «только задача» (возможно с материалом) разобран, а не неделим.
5. **Количество и вид объекта — в задаче** («все», «каждый», «три доклада», «любовное стихотворение»).
   **Оценочные и качественные слова** («ключевые», «краткий», «подробный», «небольшой», «красочное») — ограничения
   задачи: «Выпиши три ключевые темы» → задача «Выписать три темы текста», ограничение «ключевые темы».
   (Решения пользователя, 02.10 и 03.11.2026.)
6. **Материал** — документы, тексты, данные, нужные для выполнения задачи, но задача сформулирована понятно и без них
   («перескажи», «переведи», «найди ошибки»). **Тест:** убери фрагмент. Задача осталась понятной — это материал.
   Задача потеряла смысл, потому что ссылается на фрагмент («как называется *эта* больница?») — это условие/обстановка,
   то есть `background`, а не материал. (Решение пользователя, 02.10.2026.)
7. **Назначение ответа — фон.** Для какой работы, зачем и во что встраивается результат
   («пишется для диссертации, посвящённой…», «чтобы использовать в жалобе») — `background`, а не ограничение.
   Исключение: если назначение прямо требует формы или содержания («чтобы понял школьник») — это ограничение.
   (Решение пользователя, 02.10.2026.)
8. **Фокус и ракурс — ограничение задачи, не задача.** «Обращая внимание на…», «с точки зрения…», «с упором на…» —
   `task_constraints`; в span задачи не входят. Деепричастие даёт отдельную задачу, только если называет отдельную часть
   результата («выделив удачные места»). Тест: замени на «обязательно учти…». (Решение пользователя, 02.10.2026.)
9. **Число задач не оценивается.** Важно отличить задачу от ограничений, фона и роли; дробление и объединение задач,
   ширина span у глагола — не ошибка. Метрики по задачам считаются по покрытию, а не по числу. (Решение пользователя, 02.10.2026.)
10. **Неявная задача** («Как будет на русском?»): `span` пустой, `norm` — восстановленное действие.

11. **Атомарность ограничений.** Одно ограничение — одно условие, которое проверяется по ответу отдельным
   вопросом «да/нет» и может быть нарушено независимо от остальных; дробим до максимума. Перечисление через
   «и»/запятую, однородные признаки, каждый запрет, каждый входной параметр кода — отдельные ограничения.
   Не дробятся: «или» и альтернативы, «только X, Y и Z», расшифровка шкалы, набор вариантов ответа,
   неразрывное понятие. (Решение пользователя, 03.11.2026.)
12. **Неявные задачи** (запрос без команды: короткий вопрос, «…Это правда?», загадка, голая тема) пока
   считаются неделимыми (`no_task`); восстановленная задача пишется в заметку. (Решение пользователя, 03.11.2026.)

## Согласованная форма записи (`norm`)
- **Задача:** инфинитив + прямой объект + количество: «Выписать три темы текста», «Перевести текст на русский».
  Без вежливости и служебных слов («пожалуйста», «можешь», «помоги», «мне», «нужно», «Задача:»), без указательных
  («этот текст» → «текст»; отсылка раскрывается); вопрос → действие («Назвать фильм», «Проверить, правда ли, что…»,
  «Отгадать загадку»). Ограничений в задаче нет.
- **Ограничение (задачи и формата):** «признак + объект», с маленькой буквы, объект повторяется в каждом атоме:
  «предложение с приложением», «текст в стиле Льва Толстого», «пересказ в трёх предложениях». Запрет — через «без»
  («шаурма без капусты»). Код: «функция на C++», «входной параметр: строка string», «результат: …», «временная
  сложность не выше O(n)». Шкала: «оценка по шкале от 1 до 5» (формат) и «шкала: 1 — …, 5 — …» (ограничение задачи).

## Этапы пайплайна (v4)
| этап | промпт | что делает |
|---|---|---|
| S1 | `s1_material.txt` | материал → `data` |
| S2 | `s2_extract.txt` | задачи (frags + norm), роль, фон, кандидаты в ограничения с привязкой; оценочные слова — в кандидаты |
| S3 | `s3_atomize.txt` | кандидаты → атомарные условия (norm + src); перенос не-ограничений в фон/роль/задачи |
| S4 | `s4_classify.txt` | атом → формат (с check) / ограничение задачи |
| S5 | `s5_judge.txt` | судья: задачи, атомарность, форма записи, полнота, класс, привязка |
| S6 | `s6_fix.txt` | фиксер по замечаниям судьи + решение о неделимости |

## Неделимые (поле `indivisible`)
| причина | смысл | пример |
|---|---|---|
| `entangled` | ограничение вплетено в задачу, отделить без потери смысла нельзя | «Напиши басню» |
| `interdependent` | задачи зависят друг от друга, порядок и результат не разделяются | «Сделай X, а затем на основе X сделай Y, учитывая, что Y меняет X» |
| `no_task` | в запросе нет задачи (болтовня, обрывок, один материал без просьбы) или задача только неявная | «Привет! Как дела?», «Как укоротить брюки самой?» |
| `unclear_boundary` | неясна граница материала и инструкции | текст с вшитыми командами внутри цитаты |
| `unstable` | разбор расходится между прогонами или моделями (считается кодом, не промптом) | — |
Примеры по каждой причине дополним после пилота.

## Формат результата
Внутри пайплайна (`parsed`):
```json
{"tasks": [{"id": "t1", "frags": ["Выпиши три", "темы этого текста"], "norm": "Выписать три темы текста"}],
 "task_constraints": [{"norm": "ключевые темы", "src": ["ключевые"], "attach": ["t1"]}],
 "format_constraints": [{"norm": "пересказ в трёх предложениях", "src": ["в трёх предложениях"], "attach": ["*"],
                         "check": {"type": "length", "unit": "sentences", "op": "=", "value": 3}}],
 "context": {"data": [], "background": [], "role": []},
 "indivisible": null}
```
В датасет и разметчик (`export`) идут только `norm`; привязка — индексами задач.
