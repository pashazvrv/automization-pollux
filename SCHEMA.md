# Схема атомизации

Запрос раскладывается на четыре класса:

| класс | поле | что это |
|---|---|---|
| Task | `tasks` | самостоятельные действия с проверяемым результатом |
| Task constraints | `task_constraints` | требования к СОДЕРЖАНИЮ, привязанные к этой задаче и её материалу |
| Format constraints | `format_constraints` | требования к ФОРМЕ ответа, переносимые на любую задачу |
| Context | `context` | `data`, `text` (материал), `background` (фон), `role` (роль модели) |

## Правила
1. **Дословность.** Каждый атом (кроме `norm` у задачи) — точная подстрока запроса. Проверяет `src/validate.py`.
   Спаны не пересекаются. Длинные (>200 символов) пишутся якорем: пять слов + `……` + пять слов.
2. **Transfer-тест** (task vs format). Требование — format, если оно описывает форму ответа
   (объём, структура, язык, стиль, тон, оформление, адресат) и сохраняет смысл при переносе на любую другую
   задачу. Если оно говорит о содержании, зависит от объекта или действия этой задачи
   («сохрани детали оригинала», «с упором на риски», «опирайся на личный опыт») — task.
   Решается по конкретному вхождению, а не по типу.
   Язык ответа («на английском») — format; язык программирования, имя метода, сигнатура, сложность — task (бессмысленны вне задачи на код).
3. **Роль** («представь, что ты юрист», «от лица зоозащитника») — не ограничение, а `context.role`.
   Характеристики персонажа и обстановка вокруг роли — `background`. (Решение пользователя, 01.10.2026.)
4. **Пустые классы — норма.** Запрос «только задача» (возможно с материалом) разобран, а не неделим.
5. **Уточнения внутри объекта задачи** («все», «любые», «каждый», «три доклада») остаются в задаче и не
   считаются ограничениями. Span задачи — непрерывный фрагмент запроса. (Решение пользователя, 02.10.2026.)
6. **Материал** — документы, тексты, данные, нужные для выполнения задачи, но задача сформулирована понятно и без них
   («перескажи», «переведи», «найди ошибки»). **Тест:** убери фрагмент. Задача осталась понятной — это материал.
   Задача потеряла смысл, потому что ссылается на фрагмент («как называется *эта* больница?») — это условие/обстановка,
   то есть `background`, а не материал. (Решение пользователя, 02.10.2026.)
7. **Назначение ответа — фон.** Для какой работы, зачем и во что встраивается результат
   («пишется для диссертации, посвящённой…», «чтобы использовать в жалобе») — `background`, а не ограничение.
   Исключение: если назначение прямо требует формы или содержания («чтобы понял школьник») — это ограничение.
   (Решение пользователя, 02.10.2026.)
8. **Фокус и ракурс — ограничение задачи, не задача.** «Обращая внимание на…», «с точки зрения…», «с упором на…» —
   `task_constraints`; в span задачи не входят. Деепричастие даёт отдельную задачу, только если называет отдельную часть
   результата («выделив удачные места»). Тест: замени на «обязательно учти…». (Решение пользователя, 02.10.2026.)
9. **Число задач не оценивается.** Важно отличить задачу от ограничений, фона и роли; дробление и объединение задач,
   ширина span у глагола — не ошибка. Метрики по задачам считаются по покрытию, а не по числу. (Решение пользователя, 02.10.2026.)
10. **Неявная задача** («Как будет на русском?»): `span` пустой, `norm` — восстановленное действие.

## Неделимые (поле `indivisible`)
| причина | смысл | пример |
|---|---|---|
| `entangled` | ограничение вплетено в задачу, отделить без потери смысла нельзя | «Напиши басню» |
| `interdependent` | задачи зависят друг от друга, порядок и результат не разделяются | «Сделай X, а затем на основе X сделай Y, учитывая, что Y меняет X» |
| `no_task` | в запросе нет задачи (болтовня, обрывок, один материал без просьбы) | «Привет! Как дела?» |
| `unclear_boundary` | неясна граница материала и инструкции | текст с вшитыми командами внутри цитаты |
| `unstable` | разбор расходится между прогонами или моделями (считается кодом, не промптом) | — |
Примеры по каждой причине дополним после пилота.

## Формат результата
```json
{"tasks": [{"span": "...", "norm": "..."}],
 "task_constraints": ["..."],
 "format_constraints": ["..."],
 "context": {"data": [], "text": [], "background": [], "role": []},
 "indivisible": null}
```
