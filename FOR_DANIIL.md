# Инструкция: прогон очереди экспериментов (v5, GLM)

## Что это

Пайплайн атомизации запросов (S1→S6) на GLM через gigagateway + автоматическая
оценка качества по эталону. Всё обёрнуто в один скрипт: окружение, конфиг,
проверка доступа, очередь из 4 экспериментов (G0, G2, G4, G5), дашборды,
упаковка результатов.

## Что нужно заранее

1. Ничего скачивать не нужно: скрипт `run.sh` сам склонирует репозиторий.
2. Python 3.10+ (с модулем venv; на Ubuntu это пакет `python3-venv`,
   на macOS достаточно `xcode-select --install`).
3. Ключ гейтвея и имя модели — передаются переменными окружения:
   - `LLM_KEY` — ключ X-Api-Key для gigagateway;
   - `LLM_MODEL` — имя GLM на гейтвее;
   - `LLM_MODEL_JUDGE` — модель-судья; необязательно, по умолчанию = LLM_MODEL.

## Запуск — одна команда

```bash
LLM_KEY=... LLM_MODEL=... bash run.sh
```

Скрипт сам: создаст venv и поставит зависимости → сгенерирует `.env` →
проверит эндпоинты → прогонит очередь G0 → G2 → G4 → G5 →
соберёт `results_bundle.tar.gz`. По окончании прислать этот архив обратно.

Если `.env` уже лежит в корне — переменные не нужны: просто `bash run.sh`.

## Что будет происходить

- После каждого шага строится HTML-дашборд (`results/dashboards/`), логи — в `results/logs/`.
- Всё кэшируется: прерывание (Ctrl+C, падение, перезапуск задачи) ничего не ломает,
  повторный запуск продолжит с места остановки.
- Если гейт G0 не пройден (ошибки стадий ≥5% или точные спаны ≤95%) — очередь
  остановится сама и напишет почему. Это значит, что промпты надо чинить под GLM:
  дальше не гнать, прислать архив и вывод консоли.
- Ориентировочное время: G0 — минуты, G2 — самый длинный (300 запросов × 6 стадий
  + матчинг + судья), G4 и G5 — примерно треть и половина G2. Зависит от GLM.

## Варианты запуска (если нужно разнести по задачам планировщика)

Аргументы пробрасываются в оркестратор:

```bash
bash run.sh --only g0     # обязательно первым
bash run.sh --only g2     # только после успешного g0
bash run.sh --only g4     # только после g2 (сравнивает с ним)
bash run.sh --only g5     # независим, можно параллельно
bash run.sh --from g2     # продолжить очередь с шага g2
bash run.sh --workers 16  # больше параллелизма
bash run.sh --force       # идти дальше даже при провале гейта G0
```

Зависимости между шагами: g2 зависит от гейта g0; g4 зависит от результатов g2
(скрипт стабильности сравнивает g4 с g2); g5 ни от чего не зависит.

## Что прислать обратно

`results_bundle.tar.gz` (создаётся автоматически). Если очередь упала —
дополнительно текст ошибки из консоли.

## Типичные проблемы

- «задай ключ: LLM_KEY=... bash run.sh» — не переданы переменные и нет `.env`.
- 401/403 от гейтвея — ключ неверный.
- 404 модель — имя в `LLM_MODEL` не совпадает с именем на гейтвее.
- SSL-ошибки из Python — `LLM_USE_CURL=1 bash run.sh` (запасной путь через curl).
- «venv не создался» — `apt install python3-venv` (или аналог).
- Массовые «сбой разбора» на G0 — модель не держит формат; стоп, прислать результаты.
